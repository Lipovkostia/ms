# Инструкции Codex для AI Sales Center

## Подключённые проектные скиллы

При выполнении подходящей задачи прочитайте соответствующий SKILL.md **до изменений**. Эти файлы — инструкции проекта; наличие папки не означает, что инструменты браузера или внешние плагины установлены. Не утверждайте, что скилл активирован в глобальном каталоге, если это не подтверждено.

- Создание или изменение интерфейса: [interface-design](.agents/skills/interface-design/SKILL.md).
- Функции, интеграции, хранение, авторизация: [web-architecture](.agents/skills/web-architecture/SKILL.md).
- Проверки, исправления и публикация: [verify-and-release](.agents/skills/verify-and-release/SKILL.md).

Для полной реализации функции применяйте все подходящие скиллы. Для небольшой правки используйте только необходимые. Инструкции пользователя имеют приоритет. Решайте обычные обратимые вопросы самостоятельно; спрашивайте только о действительно необходимых данных или решениях.

## Контекст проекта

- Python 3.12+, Streamlit, Pandas, Plotly; запуск `streamlit run app.py`.
- Интерфейс на русском. Используйте рубли и Europe/Moscow для дат пользователя.
- Источник данных — реальный Мой Склад; генератор tests/fixtures.py доступен только тестам. Не возвращайте деморежим и не придумывайте финансовые результаты, наличие, синхронизацию или статус интеграции.
- Аналитика — проверяемые формулы Python. AI готовит предложения и черновики, не заменяет расчёты.
- Сообщения клиентам не отправлять автоматически. Изменение этого поведения требует явного указания пользователя.
- API-ключи не помещать в код, Git, отчёты, скриншоты или журналы. Не просить значения секретов в чате.
- Персональные записи разделены по аккаунту Моего Склада и сотруднику. SQLite непостоянна в Streamlit Cloud; для постоянного хранения нужен внешний PostgreSQL.
- Не менять Streamlit на другой стек и не переписывать весь проект ради косметического улучшения. Объяснить ограничения, если задача требует смены архитектуры.

## Работа в облаке

Используйте существующий checkout; не создавайте worktree без запроса. Используйте готовую `.venv`, когда её зависимости актуальны. Не обновляйте зависимости без необходимости. Сначала изучайте изменения и структуру, затем реализуйте и проверяйте.

Проверки приложения: `.venv/bin/python -m unittest discover -s tests -v`. Для правок только документации достаточно проверки ссылок, инструкции и `git diff --check`; полный набор тестов приложения не требуется.

Публикация в GitHub допустима при действующем поручении пользователя; не считать установку этих скиллов бессрочным разрешением на публикацию любого будущего изменения. Не делать force push. Сохранять чужие изменения. Подтверждать отдельно: локальные проверки, отправку в GitHub и фактическое обновление хостинга.
