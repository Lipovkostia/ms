# Дизайн интерфейса

## Когда применять

Создание страницы, редизайн, улучшение навигации, карточек, графиков, форм или мобильного интерфейса. До работы коротко сообщите пользователю, что применяете этот скилл.

## Порядок работы

1. Изучите существующий интерфейс и визуальный образец пользователя. Выделите основные действия пользователя, важные данные и состояния. При отсутствии образца выберите конкретное направление сами, не задерживая работу ради необязательных вопросов.
2. Задайте небольшую дизайн-систему: типографика, цвета, отступы, радиусы, границы и состояния элементов. Для этого проекта: светлый фон, тёмно-синяя навигация, белые карточки, зелёные положительные показатели и оранжевые предупреждения. Храните стили централизованно в sales_center/theme.py; избегайте случайного CSS в каждой странице.
3. Спроектируйте иерархию: один главный заголовок, понятное основное действие, вторичные действия и детали по запросу. Не перегружайте первый экран всеми таблицами и настройками. Рабочее место менеджера: список клиентов, карточка выбранного клиента, рекомендации и следующий контакт.
4. Реализуйте согласованные компоненты и состояния: загрузка, пустые данные, ошибка, успех, отключённая интеграция и недоступное действие. Используйте точные русские подписи и объясняйте, что действительно произошло. Время последней синхронизации — фактическое, индикатор подключения — по проверенному ответу API.
5. Проверьте ноутбук и мобильный экран. Три колонки должны превращаться в читаемую последовательность. Не уменьшайте текст до нечитаемого размера ради сохранения сетки; таблицам обеспечьте понятную прокрутку. Приоритетные кнопки доступны пальцем, подписи не обрезаются.
6. При доступном браузере снимите экраны и сравните их с образцом: композиция, плотность, размеры, выравнивание и цвета. Исправьте обнаруженное. Без браузера не называйте визуальную проверку выполненной: проведите доступные функциональные проверки и укажите предел проверки.

## Критерии качества

- Основное действие и важнейшие показатели заметны сразу.
- Отступы и типографика согласованы; нет декоративных карточек без полезной информации.
- Цвет не единственный способ передать статус; есть текст. Контраст обычного текста стремится к WCAG AA 4.5:1.
- Формы имеют подписи, понятные ошибки и явно обозначенное сохранение. Enter работает там, где пользователь ожидает отправку формы.
- Графики объясняют период, единицы и смысл; финансовые оценки обозначены как оценки.
- Не добавляйте вымышленные аватары сотрудников, рост продаж, экономию времени или число уведомлений ради внешнего вида.
- Используйте изображения и иконки только там, где они помогают. Новая библиотека или платный сервис не нужны для каждой косметической правки.

## Как ускорять работу

Переиспользуйте стиль и существующие компоненты, сначала завершите главный сценарий, затем вспомогательные состояния. Сохраняйте согласованность вместо создания отдельных визуальных решений для каждой страницы. Не обещайте точное воспроизведение макета без проверки результата в браузере.
