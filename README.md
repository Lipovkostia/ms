# AI Sales Center

Русский AI-центр оптовых продаж: Streamlit, Python 3.12+, Pandas, Plotly, SQLite или PostgreSQL. Приложение использует **только реальные данные Моего Склада**. Тестовый генератор находится исключительно в tests/ и никогда не запускается приложением.

## Запуск и публикация

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
streamlit run app.py
```

Для Streamlit Community Cloud: Repository `Lipovkostia/ms`, Branch `main`, Main file path `app.py`. После сохранения изменений в GitHub хостинг обновляет приложение автоматически. В Advanced settings выберите Python 3.12. Приложение может перезапускаться при обновлении кода.

## Подключение прямо на сайте — один ввод

1. В верхней панели нажмите **«Подключить Мой Склад»**.
2. Введите токен и оставьте включённым **«Запомнить подключение на этом устройстве»**.
3. Нажмите **«Загрузить / обновить данные»**. Дождитесь сообщения **«Подключение запомнено на этом устройстве»**.

Для этого режима **не нужны Settings, Secrets или настройка внешней базы**. Токен и последний успешный снимок сохраняются в IndexedDB браузера, зашифрованными AES-GCM. Ключ Web Crypto создаётся с `extractable=false`, сохранение транзакционное. Компонент не подключает сторонние скрипты и принимает сообщения только от родительской страницы того же origin. Снимок подписан HMAC с привязкой к токену; большие идентификаторы передаются как часть JSON-строки, без округления чисел JavaScript.

После обновления кода, закрытия вкладки, новой сессии или перезапуска сервера **тот же браузер на том же адресе** автоматически восстанавливает подключение и данные. Даже если облако удалит серверную SQLite, браузерный снимок останется доступен. Его исходная дата показана в интерфейсе; устаревший снимок обновляется в фоне, а сохранённая база остаётся доступной. Таймер состояния проверяется каждые 2 секунды. Повреждённый снимок не выдаётся за данные API: приложение загрузит историю заново с сохранённым ключом.

Хранение относится к браузеру, профилю пользователя, адресу сайта и сотруднику приложения. После очистки данных сайта, смены браузера/домена или окончания приватного режима потребуется повторный ввод. На общем компьютере используйте отдельные профили браузера или **«Забыть подключение на этом устройстве»**. Без флажка токен используется только в сессии. Если браузер запретил хранение, приложение покажет ошибку; разовое подключение остаётся доступным. При ожидании восстановления есть кнопка «Ввести токен вручную».

По умолчанию данные обновляются каждые **30 минут при открытой вкладке**, интервалы: вручную/15/30/60 минут. Новые периодические обновления запускаются при открытой вкладке. Уже запущенная серверная задача может завершиться после её закрытия; это не постоянный фоновый сервис. «Обновить сейчас» запускает чтение API в фоне. «Отключить источник в этой сессии» не удаляет браузерную запись. Только «Забыть подключение» удаляет её для текущего сотрудника. Ошибка API не перезаписывает прежний снимок и ключ. Шифрование защищает сохранённую запись; сам браузер и сервер приложения должны быть доверенными, токен используется ими для разрешённых API-запросов.

Прикладная серверная база не хранит токены. Задачи и заметки по-прежнему хранятся в SQLite/PostgreSQL отдельно: браузерное сохранение подключения не делает их постоянными на облачном диске. Для постоянного общего хранения задач нужен PostgreSQL (`DATABASE_URL`).

### Дополнительно: общий серверный ключ

Прежний способ через защищённые настройки хостинга остаётся необязательным. При его использовании общий `MOYSKLAD_TOKEN` разрешён только после OIDC-входа либо подтверждённого закрытого доступа (`MOYSKLAD_PRIVATE_DEPLOYMENT=true`). Флаг сам не закрывает хостинг. Для нового браузерного способа эти параметры не нужны: каждый сотрудник вводит свой ключ один раз на своём устройстве. OIDC разделяет записи сотрудников; без него действует персональный режим.

Система читает проведённые отгрузки за 12 месяцев, товары, типы цен и группы. Каждая синхронизация повторно читает годовую историю; обновление одного прайс-листа читает только каталог и валюты. В Мой Склад ничего не записывается. Тестовые данные не используются в production.

## Интерфейс и работа менеджера

Главная, клиенты, карточка клиента, возврат, товарная аналитика, рекомендации, задачи, эффективность, сообщения и настройки. Клиентское рабочее место содержит список с поиском и приоритетами, карточку с вкладками, графики и панель рекомендаций с черновиком и задачей. Нет вымышленных показателей экономии времени, наличия товаров или результатов AI.

Задачи сохраняются кнопкой «Создать задачу», результаты — «Сохранить изменения», заметки — «Сохранить заметку», черновики — «Сохранить черновик». Сам ввод в поле не сохраняет запись в базу. Текст можно скопировать из блока кода. Экспорт своих записей доступен в «Сообщениях». Задачи, заметки, черновики, отметки обработки и выбор модели отделены по аккаунту Моего Склада и сотруднику. В Мой Склад эти записи не передаются. Продажи не приписываются действиям менеджера.

## Постоянное хранение

По умолчанию записи лежат в `.runtime/moysklad.db` (SQLite), папка исключена из Git. На своём компьютере файл сохраняется между запусками. **На Streamlit Cloud локальный диск непостоянен: записи могут исчезнуть при перезапуске или переразвёртывании.** Для постоянного хранения создайте внешнюю PostgreSQL и добавьте `DATABASE_URL` в Streamlit Cloud → App settings → Secrets:

```toml
DATABASE_URL = "postgresql://USER:PASSWORD@HOST:5432/DB?sslmode=require"
```

Это пример с заполнителями. Реальные реквизиты вводятся только в Secrets. Приложение создаёт таблицы автоматически, не сохраняет API-ключи в них. Резервное копирование настраивается у провайдера PostgreSQL. Подключение к конкретной внешней базе требует её реквизитов; без них проверены SQLite и изоляция записей, а не реальная PostgreSQL. Старые анонимные записи остаются в `legacy` и не присваиваются автоматически сотрудникам.

## Несколько сотрудников

Вход поддерживает OIDC средствами Streamlit. Настройте приложение у вашего провайдера входа, redirect URI: `https://ВАШ-ДОМЕН.streamlit.app/oauth2callback`. Добавьте Secrets (корневые параметры идут **перед** секцией `[auth]`):

```toml
allowed_emails = ["manager@example.com", "owner@example.com"]
# DATABASE_URL = "postgresql://..."

[auth]
redirect_uri = "https://ВАШ-ДОМЕН.streamlit.app/oauth2callback"
cookie_secret = "СЛУЧАЙНАЯ_ДЛИННАЯ_СТРОКА"
client_id = "CLIENT_ID_ПРОВАЙДЕРА"
client_secret = "CLIENT_SECRET_ПРОВАЙДЕРА"
server_metadata_url = "https://accounts.google.com/.well-known/openid-configuration"
```

Пример использует Google OIDC. После настройки вход обязателен и разрешён только email из списка. У каждого сотрудника отдельные записи и выбранная AI-модель; общий токен Моего Склада можно настроить постоянно через Secrets, ключи AI остаются в сессии сотрудника. Без `[auth]` действует **персональный режим без отдельных учётных записей**. Не используйте этот режим как общий доступ сотрудников. Роли, общие задачи команды и автоматическое назначение менеджера по данным Моего Склада пока не реализованы.

## WhatsApp, Telegram, MAX и OpenRouter

В «Настройках» можно проверить реальные подключения:

- WhatsApp — ID инстанса и токен Green API, запрос `getStateInstance`. `notAuthorized` означает, что WhatsApp ещё нужно авторизовать в Green API; успешный HTTP-запрос не равен готовности отправлять.
- Telegram — токен бота, проверка `getMe` официального Bot API.
- MAX — токен бота, проверка `/me` официального Bot API v2 (`platform-api2.max.ru`). MAX и Telegram не выдаются за подключения через WhatsApp API.
- OpenRouter — ключ, проверка `/auth/key` и загрузка актуального каталога `/models`. В карточке клиента выбирается модель; «Сохранить мою модель» запоминает выбор для сотрудника.

OpenRouter генерирует AI-черновик по кнопке после явного разрешения передать имя клиента и агрегаты. Телефон, email и полная история не передаются. Запрос может тарифицироваться выбранной моделью. Формулы и приоритеты рассчитывает Python; AI не заменяет финансовую аналитику. Ключ OpenRouter остаётся в памяти сессии, при её окончании нужно подключиться повторно.

**Входящие сообщения, отправка через API и автономная работа с клиентами пока не реализованы.** Сейчас мессенджеры проверяют подключение, а сообщения отправляются менеджером вручную после проверки. Никакие сообщения клиентам автоматически не отправляются. Для проверки ваших реальных Green API/ботов/OpenRouter требуются соответствующие ключи; тесты адаптеров используют подставленные ответы API.

## Проверяемые формулы и ограничения

- Выручка строки без НДС = цена × количество × (1 − скидка/100), с исключением включённого НДС. Сумма позиций с НДС сверяется с суммой документа. Только RUB/643; другая валюта останавливает загрузку.
- Себестоимость = исторический `stock.cost` (копейки) / 100 × количество. Валовая прибыль = выручка − себестоимость. Если API не вернул себестоимость, итог прибыли за такой период недоступен; ноль не подставляется.
- Средний чек = оборот / число уникальных отгрузок; маржинальность = прибыль / оборот × 100%.
- Средний интервал = среднее разниц дат заказов; обычный цикл = медиана при ≥3 заказах.
- Частота = число заказов × 30 / число дней от первого заказа до сегодня (минимум 1).
- Отклонение = дней без покупки / обычный цикл. Более 1,5 — высокий приоритет, более 1,1 — средний. Недостаточная история не означает потерю клиента.
- Совместные покупки = число заказов, содержащих оба товара.

Возвраты, розничные продажи, расходы на логистику и налоги не учитываются: показатели описывают проведённые отгрузки, а не чистые продажи или бухгалтерскую прибыль. Внутренние отгрузки своим организациям и пустые документы без позиций исключаются. Сегмент не угадывается; путь группы товара служит категорией. Наличие и текущие цены не подтверждаются. Рекомендации используют всю историю, графики и финансовые метрики — выбранный период.

Потенциальный эффект всегда **оценка** дополнительного оборота: возврат — исторический средний чек; снижение — разница первого и третьего полных месяцев; рост — 15% среднего чека. Это не обещание прибыли. Предложения сопутствующего товара с расчётом эффекта не создаются без подтверждённой ценовой модели. Загрузка не является транзакционным снимком API; изменение документов во время чтения может потребовать повторной попытки. Лимит коллекции — 100 000 записей; превышение останавливает загрузку.

## Архитектура и проверки

`app.py` — интерфейс; `theme.py` — оформление; `settings.py` и `identity.py` — подключения и вход; `analytics.py` — формулы; `recommendations.py` — правила; `moysklad.py` — API; `live_data.py` — строгая нормализация; `sync.py` — восстановление; `fast_sync.py` — ограниченная очередь фоновых обновлений; `connection_config.py` — параметры постоянного подключения; `snapshots.py` — версионированные снимки; `device_storage.py` и `browser_vault/` — зашифрованные сжатые снимки на устройстве (`browser_store.py` сохраняет прежние импорты); `product_analytics.py` — покупатели товара; `product_design_data.py` — фильтры и экспорт; `product_page.py` и `product_page_cache.py` — экран и ограниченный кеш одной пользовательской сессии; `providers.py` — внешние сервисы; `storage.py` — SQLite/PostgreSQL.

```bash
.venv/bin/python -m unittest discover -s tests -v
```

Тесты проверяют НДС, себестоимость, валюты, циклы, неполные данные, API-ошибки, сохранение последнего снимка, изоляцию сотрудников, черновики, задачи и все страницы интерфейса. Синтетические данные доступны только тестам. Ключи и данные реального аккаунта в репозиторий не добавляются.

Проверка 12 октября 2026: реальное чтение аккаунта Моего Склада успешно — 6 320 контрагентов, 1 392 товара, 17 843 позиции, все 10 разделов проверены через AppTest на загруженной базе. Повторить сообщение «Получены неподдерживаемые данные API» в этой среде не удалось; добавлены строгие проверки обязательных полей, обработка nullable скидки/НДС и более конкретная диагностика. Журнал пользователя содержал только запуск и обновление сервера, без причины ошибки. Проверка публичного развёртывания и реальных ключей других сервисов отдельно не выполнена.

### Если после обновления возникает ModuleNotFoundError

Откройте Streamlit Cloud → Manage app → Reboot app. Проверьте, что выбраны `main`, `app.py` и журнал установки использует корневой `requirements.txt`. SQLite использует встроенный `sqlite3` и не требует SQLAlchemy. Драйвер `psycopg` импортируется только при настройке PostgreSQL; если он не установлен, приложение показывает инструкцию, а не падает на импорте.

## Дизайн рабочего места

Раздел «Клиенты» открывается первым: тёмная боковая навигация, верхняя панель поиска и синхронизации, пять карточек показателей, список клиентов, подробная карточка и панель рекомендаций. Поиск в верхней панели находит клиентов по названию, адресу, телефону/email и купленным товарам; отдельный поиск списка — по компании или городу. Клиент выбирается видимой кнопкой «Открыть …» под его карточкой; скрытых областей нажатия нет. Период аналитики и сведения о хранении находятся в боковой панели.

В карточке: столбчатая динамика покупок, кольцевая диаграмма категорий, последние проведённые отгрузки и вкладки истории, товаров, заметок и контактов. Потенциал продаж — сценарная оценка: берётся максимальная оценка рекомендации каждого клиента, затем значения суммируются, чтобы не суммировать несколько гипотез одного клиента. Экономия времени не показывается, поскольку не измеряется.

Кнопки WhatsApp/Telegram открывают веб-мессенджеры для ручной отправки; подключение провайдера и автоматическая отправка при этом не имитируются. Подготовленный текст сохраняется кнопкой, копируется из раскрываемого блока или скачивается. Компактная форма задачи предлагает контакт через пять дней; дату можно изменить, название и заметку — раскрыть.

Внешний вид проверен 12 октября 2026 в Chromium на 1600, 900 и 390 px. На узких экранах показатели и три рабочие панели перестраиваются; проверены отсутствие горизонтального переполнения, выбор клиента, поиск, сохранение черновика/копирование и создание задачи. Браузерный стенд использовал синтетические fixtures вне приложения и не опубликован. В production источник остаётся только реальным. Стили — theme.py, HTML и компактные графики — presentation.py.

Проверки постоянного подключения охватывают восстановление в новой сессии без API-запроса, защиту серверного ключа в публичном режиме, сохранение при ошибке обновления, повреждённый снимок, изоляцию пользователей/ключей и точность больших целочисленных идентификаторов. Реальная внешняя PostgreSQL и приватность размещённого приложения требуют настройки хостинга и отдельно здесь не проверены.

### Как открыть настройки

Русская кнопка «Настройки и подключения» в правом верхнем углу открывает настройки приложения. Кнопка «Настроить постоянное подключение» в панели синхронизации ведёт туда же. На странице настроек «Открыть управление сайтом» открывает панель Streamlit Cloud. Там войдите аккаунтом владельца и найдите ms → ⋮ → Settings (Настройки) → Secrets (Защищённые ключи). Внешняя панель нужна только для необязательных общих серверных настроек; для браузерного сохранения токена она не требуется. Manage app — управление хостингом, а не профиль пользователя.

Области нажатия используют обычные видимые кнопки в потоке страницы, без прозрачных слоёв поверх карточек. Панель сайта отступает от служебного заголовка Streamlit; минимальная высота основных кнопок — 44 px.

## Товары и покупатели

В «Товарной аналитике» добавлена вкладка **«Товары и покупатели»**. Выберите тип цен (по умолчанию «Цена опт безнал», если он есть), затем категорию и товар. Группы и их вложенность соответствуют `pathName` Моего Склада. В текущем прайсе показываются неархивные товары/модификации/комплекты с ценой выбранного типа; нулевые цены по умолчанию скрыты, фильтр можно выключить. Это прайс по API, не проверка наличия и не импорт отдельного Excel/PDF с дополнительными ручными правилами.

Справа отображаются все покупатели выбранного **product_id**: сумма количества, фактическая выручка без НДС, число уникальных отгрузок, дата последней покупки и число дней с неё. Одинаковые названия разных товаров не смешиваются. Позиции с нулевым количеством не считаются покупкой; бесплатные позиции с положительным количеством учитываются. Единицы измерения берутся из API; при отсутствии показаны «ед. товара», без предположений о кг/штуках. По умолчанию история — все загруженные 12 месяцев, доступен переключатель на выбранный период.

Кнопка «Открыть клиента — …» переводит в раздел «Клиенты», выбирает нужного контрагента и сбрасывает прежние фильтры, чтобы они его не скрывали. Поиск и страницы доступны и для товаров, и для покупателей. «Обновить прайс-лист» обновляет только товары/цены, без повторного чтения годовой истории. Старые снимки без цен предлагают загрузить каталог отдельно.

Проверено реальное чтение каталога 12 октября 2026: 1 392 позиции, 8 типов цен; в ненулевом действующем прайсе «Цена опт безнал» — 813 позиций, 48 групп. Проверка не подтверждает наличие этих товаров на складе. Браузерный стенд с тестовым API проверил шифрование, новую сессию, настоящий перезапуск сервера с удалением серверного снимка без повторного API-запроса, отклонение сообщений чужого origin и переход «товар → покупатели → нужный клиент». В runtime тестового источника нет.

## Блоки клиентов по давности покупки

В разделе «Клиенты» доступны четыре блока: текущие (0–30 дней, от двух покупок), остывающие (30–60), уходящие (60–90), потерянные (90–365). Нижняя граница включается, верхняя не включается. «Потерянные» — название диапазона пользователя, а не доказанный уход клиента. Последняя покупка и суммы берутся из всей доступной истории проведённых отгрузок; сумма включает НДС и не вычитает возвраты. Количество сделок в блоках — число отгрузок, не число строк товаров. Минимум покупок считается в диапазоне блока. Клиенты без покупок не включаются.

«✏️ Настроить блоки» позволяет менять названия, диапазоны и минимум покупок, добавлять или удалять блоки изменением количества (1–8). Настройки сохраняются отдельно для сотрудника и аккаунта в базе записей; SQLite в облаке может быть удалена, PostgreSQL обеспечивает постоянное хранение. Поиск и фильтр «Владелец-сотрудник» применяются ко всем блокам. Клиенты с заказом покупателя, созданным за последние 10 дней, отображаются первыми, далее — по общей сумме. Дата заказа для этого индикатора — `created`, а не `moment`; заказ не заменяет проведённую покупку. На мобильном блоки располагаются в одну колонку, на планшете и компьютере — в две.

Для старого сохранённого снимка нажмите «Загрузить данные для блоков»: полная синхронизация запускается в фоне, включая историю, сотрудников и новые заказы; текущая база остаётся доступной. Последующие обновления включают эти данные в общий снимок. Требуются права чтения контрагентов (включая архив), сотрудников, отгрузок, валют и заказов покупателей. При ошибке прежние данные сохраняются.

## Обновлённый экран товарной аналитики

«Товарная аналитика → Товары и покупатели» использует двухпанельный макет: слева каталог с поиском по названию, коду и артикулу, справа выбранный товар, три показателя и покупатели. Категории с вложенной иерархией доступны из фильтра; отдельной колонки категорий больше нет. Прайс-лист и ненулевые цены сохраняют прежние правила. Нажатие строки товара обновляет правую панель; строка покупателя открывает существующую карточку клиента. Для клавиатуры и альтернативного выбора также доступны раскрывающиеся списки переходов.

Периоды «30 дней», «90 дней», «12 месяцев» и «Весь доступный период» общие для каталога, метрик, покупателей и экспорта. Последний вариант означает всю **загруженную годовую товарную историю**, а не всю историю компании; фактические границы показываются под фильтрами. Фильтр покупателя применяется к обеим панелям. Каталог сортируется по продажам, названию, цене или объёму; экспорт CSV учитывает фильтры, сортировку и выбранный прайс, включая валюту и единицы. Объёмы разных товаров не суммируются. Текущая загрузка не содержит разбивки по складам: этот фильтр явно недоступен, показываются все доступные отгрузки.

Макет использует реальные данные приложения, без иллюстративных чисел, роста продаж или наличия. Правила НДС, возвратов, прав доступа, сохранения подключения и обновления не изменены. На узком экране панели располагаются последовательно; широкие таблицы прокручиваются внутри панелей. Старая аналитика графиков сохранена во второй вкладке «Продажи и категории», её период выбирается отдельно в боковой панели «Период графиков».

## Dashboard: новые контрагенты

В боковом меню откройте **Dashboard**. Первый блок — компактный реестр контрагентов с пятью колонками: **Контрагент**, **Дата добавления**, **Код**, **Владелец-сотрудник**, **Проект**. Высота строки — 28 px; ширину колонок можно менять перетаскиванием границы заголовков. Для открытия карточки клиента отметьте строку слева. На телефоне доступна горизонтальная прокрутка внутри таблицы.

По умолчанию выбран период последних 30 дней. Поля «Добавлены с / по» включают обе даты целиком; сортировка «Сначала новые / Сначала старые» применяется ко всему результату до разбивки на страницы. Поиск работает по названию. В кнопке **«Фильтры»** находятся сотрудник, проект, код, «За всё время» и включение архивных. Пустой код или проект выбирается как «Не указан», незакреплённый сотрудник — «Не назначен». «Сбросить фильтры» возвращает исходный период и очищает поиск.

Дата добавления берётся из `counterparty.created`, код — из `counterparty.code`, сотрудник — из `counterparty.owner` и справочника `employee`. Даты показываются по Москве. Дата изменения и первая покупка не подменяют дату создания. Если дата отсутствует в API, контрагент виден только при выборе «За всё время». В стандартной схеме контрагента Remap 1.2 поля проекта нет: колонка читает только дополнительное поле с точным названием «Проект» (также поддерживается `Project`, без учёта регистра и крайних пробелов), текстовое либо значение справочника с названием. Если поле не найдено, интерфейс сообщает об этом. Проекты из заказов клиентам не присваиваются.

**«Обновить список»** читает только активных/архивных контрагентов и сотрудников, без отгрузок, товаров и заказов. Работа идёт в фоне; фильтры и навигация не вызывают API. Старая база без новых полей при первом открытии Dashboard обновляется один раз автоматически, если подключение уже восстановлено. Результат сохраняется в прежний снимок пользователя и источника; действует существующее зашифрованное сохранение подключения в браузере. Полная синхронизация также включает поля Dashboard. Обновление списка не меняет дату последней загрузки истории продаж; в блоке отдельно указано фактическое время обновления CRM. Это снимок, не поток событий в реальном времени. Автообновление всего снимка остаётся по выбранному в подключении интервалу, пока открыта сессия.

Суммы, история покупок и заметки при обновлении CRM сохраняются. Если в CRM появился новый контрагент, его карточка доступна сразу; для включения его полной истории в блоки активности нужна общая синхронизация. Ошибка формата, повторные идентификаторы или несовпадение аккаунта сохраняют предыдущий снимок. Реальные токены и данные не добавляются в репозиторий; синтетические данные используются только в тестах.

## Быстрое открытие и обновление

При входе сначала используется подписанный снимок из браузера. Если он недоступен, приложение пробует серверный снимок для того же пользователя и токена. API читается только при отсутствии снимка или при обновлении. Переключение разделов, поиск и фильтры не запускают новую выгрузку. После восстановления компонент подтверждает получение коротким ответом: большой снимок и токен не передаются повторно при каждом действии интерфейса. Старые браузерные записи поддерживаются; большие записи сжимаются перед передачей и при сохранении без изменения идентификаторов. HMAC, привязка к источнику, AES-GCM и проверка origin сохранены. Распаковка ограничена по размеру.

Полное обновление и обновление только прайс-листа выполняются в серверных рабочих потоках (не больше двух одновременно и четырёх задач вместе с очередью). Потоки не обращаются к Streamlit session_state; проверенные результаты применяются атомарно в сессии нужного пользователя/источника. Для одной сессии не создаются повторные параллельные выгрузки. Ошибка сохраняет предыдущую базу и дату последнего успеха. Обновление прайса не выгружает отгрузки и не меняет дату обновления истории.

Товарная аналитика считает только открытое представление. Расчёты, покупатели и экспорт кешируются внутри сессии и сбрасываются при новом снимке, источнике, дате или фильтрах. Список покупателя показывает до 200 совпадений с поиском: любой контрагент остаётся доступен по имени. Первичная загрузка полного аккаунта всё ещё зависит от объёма и скорости Моего Склада; интерфейс остаётся доступным, данные появляются после проверки.

Проверка производительности 12 октября 2026 на синтетических данных: обычная навигация после восстановления снимка 10 МиБ раньше отправляла WebSocket-пакет 10 486 115 байт, после исправления — 284 байта. Расчёты на 6 320 клиентах/17 843 строках сократились с 3,053 до 0,034 секунды с совпадением результатов прежних формул. Эти измерения не обещают такой же задержки сети или холодного запуска Streamlit Cloud. Браузерная проверка подтверждает переходы между страницами во время задержанного API, единственную выгрузку, автоматическое применение результата и отсутствие переполнения на телефоне.
