# AI Sales Center

Персональный центр оптовых продаж продуктов питания. MVP на Python 3.12+, Streamlit, Pandas, Plotly и SQLite.

## Запуск

```bash
cd /workspace/ms  # или каталог вашего клона
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
streamlit run app.py
```

Откройте адрес, который напечатает Streamlit. Для облачной машины без браузера:

```bash
.venv/bin/streamlit run app.py --server.headless true --server.address 0.0.0.0
```

## Что работает

Все восемь разделов: главная, клиенты, карточка клиента, возврат клиентов, товарная аналитика, AI-рекомендации, задачи, эффективность. Доступны поиск и фильтры, графики, история заказов, редактируемые черновики сообщений, копирование из блока текста и скачивание черновика, создание задач, изменение статуса и заметок. Никакие сообщения не отправляются.

Данные генерируются воспроизводимо: 100 вымышленных компаний, 12 товаров, 12 месяцев заказов, разные сегменты и циклы. Даты сдвигаются относительно текущего дня. Все продажи, цены и возможности демонстрационные. В демонстрационном режиме действия менеджера (задачи и отметки об обработке) сохраняются в `.runtime/sales.db`. Эта папка исключена из Git. Удаление базы сбрасывает локальные задачи. База доступна всем пользователям одного экземпляра приложения: это персональный MVP без авторизации, не публичная многопользовательская CRM.

Глобальный период влияет на финансовые показатели, историю и товарную аналитику. Циклы покупок и рекомендации учитывают всю историю. В эффективности обработанные рекомендации фильтруются по дате отметки, задачи считаются за всё время. SQLite хранит время отметок в UTC.

## Проверяемые формулы

- Оборот = сумма выручки строк заказа.
- Себестоимость = количество × демонстрационная закупочная цена.
- Валовая прибыль = оборот − себестоимость, без логистики, налогов и других расходов.
- Маржинальность = валовая прибыль / оборот × 100%; при нулевом обороте — 0.
- Средний чек = оборот / число уникальных заказов; строки заказа не считаются отдельными заказами.
- Средний интервал = среднее разниц дат последовательных заказов.
- Обычный цикл = медиана интервалов при наличии минимум трёх заказов.
- Частота = число заказов × 30 / дней от первой покупки до текущего дня (знаменатель минимум 1).
- Отклонение = дней после последнего заказа / обычный цикл. Более 1,5 — высокий приоритет, более 1,1 — средний. Это сигнал задержки, а не подтверждение потери клиента.
- Сопутствующие покупки = количество заказов с обоими товарами; повторы строки товара внутри заказа не увеличивают счётчик.

Рекомендации — правила Python, а не ответы языковой модели. Возврат оценивается историческим средним чеком; сопутствующее предложение — демонстрационной ценой × 6 единиц; восстановление оборота — разницей первого и третьего из трёх полных месяцев; развитие роста — 15% среднего чека. Это сценарные оценки дополнительного оборота, не прогноз вероятности и не гарантированная прибыль. Наличие товаров и реальные цены не подтверждаются. Продажи не приписываются обработке рекомендаций.

## Мой Склад и ключи

В боковой панели выберите источник «Мой Склад», вставьте новый ключ в скрытое поле «API-токен Моего Склада» и нажмите «Загрузить / обновить данные». Режим использует только GET-запросы к `https://api.moysklad.ru/api/remap/1.2`: контрагенты, ассортимент, валюты, проведённые отгрузки за 12 месяцев и все их позиции. Данные хранятся в памяти сессии, не в Git. Источник и время загрузки явно показаны; при ошибке демонстрационные данные не подставляются. После перезапуска нужно повторить загрузку. Задачи реального режима хранятся отдельно в `.runtime/moysklad.db`.

Токен из поля используется для одной загрузки; форма очищается после отправки. Он не записывается в файлы, SQLite или кэш. Для обновления введите его повторно. Вводите токен только при локальном запуске или при доступе по защищённому HTTPS к доверенному серверу. Альтернативно `MOYSKLAD_TOKEN` читается из окружения. Для облака задайте новый ключ в защищённых настройках окружения с назначением `api.moysklad.ru`. Локально можно ввести его без отображения и записи в историю команд:

```bash
read -rsp 'Новый токен Моего Склада: ' MOYSKLAD_TOKEN
export MOYSKLAD_TOKEN
streamlit run app.py
# После завершения:
unset MOYSKLAD_TOKEN
```

Ключ, опубликованный в чате, следует отозвать и выпустить заново. Он не добавлен в проект и не использовался. Не вводите новый ключ в чат, код или README. Интеграция проверена на моделируемых ответах; реальный аккаунт в этой среде не проверен, поскольку защищённая переменная не задана.

Ограничения реального режима:

- Только RUB. Иная или неизвестная валюта останавливает загрузку, а не смешивается с рублями.
- Выручка **без НДС** рассчитывается из цены, количества и скидки; сумма с НДС проверяется против суммы отгрузки. Несовпадение останавливает загрузку.
- Себестоимость берётся из исторического `stock.cost` при `fields=stock`. Отсутствующая себестоимость не заменяется закупочной ценой или нулём: соответствующие итоги прибыли и маржинальности показывают «Нет данных».
- Возвраты, розничные продажи и комиссионные операции пока не учитываются. Метрики описывают **проведённые отгрузки**, а не чистые продажи или бухгалтерскую прибыль.
- Сегмент не угадывается, отображается «Не указан». Категория — путь группы товара из API. Без ценовой модели в реальном режиме не генерируется демонстрационное предложение оливок.
- Пустая база показывает понятное сообщение. Большие объёмы могут загружаться долго; лимит — 100 000 записей на коллекцию, превышение не выдаётся за полную загрузку.
- Загрузка не является транзакционным снимком API: изменения учётной системы во время чтения могут потребовать повторной загрузки.

Контракт API сверялся с официальной документацией: https://dev.moysklad.ru/doc/api/remap/1.2/ (позиции отгрузки, `fields=stock`, НДС). Все сетевые вызовы проверяют TLS, не следуют перенаправлениям и не выводят ключи.

## Архитектура

- `app.py` — интерфейс и навигация.
- `sales_center/data.py` — демонстрационный источник.
- `sales_center/analytics.py` — расчёты.
- `sales_center/recommendations.py` — бизнес-правила и черновики.
- `sales_center/storage.py` — параметризованные запросы SQLite.
- `sales_center/moysklad.py` — read-only клиент API.
- `sales_center/live_data.py` — нормализация реальных отгрузок.
- `.streamlit/config.toml` — тема.
- `tests/` — проверки формул, сценариев и интерфейса.

## Проверки

```bash
.venv/bin/python -m unittest discover -s tests -v
```

Визуальная адаптация основана на сетке Streamlit и CSS для небольших экранов; отдельный браузерный тест на мобильном устройстве не выполнялся. Для production нужны авторизация, защита доступа, резервное копирование, реальные источники данных и интеграционные проверки.
